# 选课注册系统（Course Registration System）

2026 年软件工程实践项目（Software Engineering Practice Project）  
计算机科学与技术学院（College of Computer Science & Technology）  
**实践周期：2026.9.8 — 2026.10.16**

本文档根据《2026年软件工程课程设计题目.pdf》（Course Registration Requirements）整理并翻译为中文，作为课程设计需求说明。

---

## 1. 问题陈述

作为 Wylie 学院信息系统负责人，你需要开发一套新的**学生选课注册系统**。学院希望用新的**客户端/服务器系统**替换基于大型机技术的旧系统。

新系统应支持：

- 学生通过接入校园局域网（LAN）的个人电脑**选课**、**查看成绩单（报告卡）**；
- 教授通过系统**报名授课**、**录入成绩**。

由于联邦拨款减少，学院无法一次性替换全部系统，因此将**保留现有课程目录数据库**。该库是运行在 DEC VAX 上的 Ingres 关系数据库。学院已投入开放 SQL 接口，可从学院的 Unix 服务器访问该库。

遗留系统性能较差，新系统必须保证对遗留数据的访问足够及时。新系统**只读取**课程目录信息，**不更新**该库。课程信息仍由教务处通过另一套系统维护。

### 1.1 业务规则摘要

| 规则 | 说明 |
| --- | --- |
| 学期初目录 | 学生可获取本学期开课一览，含授课教授、所属院系、先修课程等信息 |
| 选课数量 | 每位学生选择 **4 门首选课程**，另选 **2 门备选课程** |
| 开课人数 | 每门课程开设（Course Offering）最多 **10** 人、最少 **3** 人；不足 3 人则取消 |
| 改选期 | 每学期有一段时间允许学生改课表（加课/退课） |
| 计费 | 学生完成注册后，系统向计费系统发送信息以便收费 |
| 满员通知 | 注册过程中若某课已满，须在学生提交课表前通知该学生 |
| 成绩查看 | 学期结束后学生可查看电子成绩单；成绩属敏感信息，须加强安全防护 |
| 教授职责 | 教授可选择所授课程、查看选课学生名单、录入各班成绩 |

## 3. 补充规格说明（Supplementary Specification）

### 3.1 目的与范围

本文档定义**用例模型不易表达**的需求。补充规格与用例模型一起构成系统完整需求。

本规格适用于由 OOAD 学生开发的选课注册系统，主要定义：

- 非功能需求：可靠性、可用性（易用性）、性能、可支持性等；
- 跨多个用例的公共功能需求。

（功能需求详见各用例规格。）参考文献：无。

### 3.2 功能性（跨用例）

- 必须支持**多用户并发**工作。
- 学生正在组课表时，若某所选开课班次已满，必须通知该学生。

### 3.3 易用性

桌面用户界面应兼容 **Windows 95/98**。

### 3.4 可靠性

系统应 **7×24 小时**可用，停机时间不超过 **10%**。

### 3.5 性能

- 中心数据库同时在线用户不超过 **2000** 人；本地服务器同时在线用户不超过 **500** 人。
- 访问遗留课程目录数据库的延迟不超过 **10 秒**。  
  **说明：** 基于风险的原型表明，若不创造性地使用中间层处理能力，遗留课程目录库无法满足性能需求。
- **80%** 的事务须在 **2 分钟**内完成。

### 3.6 可支持性

无。

### 3.7 安全性

- 学生不得修改他人课表；教授不得修改其他教授已分配的开课班次。
- **只有教授**可为学生录入成绩。
- **只有注册管理员（Registrar）**可修改任何学生信息。

### 3.8 设计约束

- 系统须与现有遗留系统——**课程目录系统**（RDBMS）集成。
- 系统须提供基于 Windows 的桌面界面。

## 5. 用例规格

各用例结构与原文一致：简要说明、事件流、备选流、特殊需求、前置条件、后置条件、扩展点。未特别说明的特殊需求与扩展点均为“无”。

### 5.1 登录（Login）

**简要说明：** 描述用户如何登录选课注册系统。

**基本事件流**（参与者希望登录时开始）

1. 参与者输入姓名和密码。
2. 系统校验姓名与密码，并将参与者登录进系统。

**备选流**

- **姓名/密码无效：** 系统显示错误信息。参与者可返回基本流起点重新输入，或取消登录并结束用例。

**前置条件：** 系统处于登录状态，并显示登录界面。  
**后置条件：** 成功则参与者已登录；否则系统状态不变。

---

### 5.2 维护教授信息（Maintain Professor Information）

**简要说明：** 注册管理员在系统中增加、修改、删除教授信息。

**基本事件流**（注册管理员希望增改删教授信息时开始）

1. 系统请注册管理员选择功能：增加教授、更新教授、或删除教授。
2. 根据选择执行对应子流。

**增加教授**

系统要求录入：姓名、出生日期、社会保障号、状态、所属院系。

1. 注册管理员提交后，系统生成并分配唯一教授编号，将教授加入系统。
2. 系统向注册管理员返回新教授编号。

**更新教授**

1. 系统要求输入教授编号。
2. 注册管理员输入编号，系统检索并显示教授信息。
3. 注册管理员修改所需字段（同“增加教授”中的信息项）。
4. 系统更新该教授记录。

**删除教授**

1. 系统要求输入教授编号。
2. 系统检索并显示教授信息。
3. 系统提示确认删除。
4. 注册管理员确认。
5. 系统删除该教授。

**备选流**

- **教授未找到：** 指定编号不存在时显示错误。管理员可改输编号或取消操作并结束用例。
- **取消删除：** 管理员决定不删除时，取消删除并回到基本流起点。

**前置条件：** 注册管理员已登录。  
**后置条件：** 成功则教授信息已增加、更新或删除；否则系统状态不变。

---

**增加学生**

系统要求录入：姓名、出生日期、社会保障号、状态、毕业日期。

1. 提交后系统生成并分配唯一学生编号，将学生加入系统。
2. 系统向注册管理员返回新学生编号。

**更新学生**

1. 系统要求输入学生编号。

4. 系统更新学生信息。

**删除学生**

1. 系统要求输入学生编号。
2. 检索并显示学生信息。
3. 提示确认删除。
4. 管理员确认。
5. 系统删除该学生。

**备选流**

- **学生未找到：** 编号不存在时显示错误。管理员可改输编号或取消操作并结束用例。
- **取消删除：** 决定不删除时取消删除并回到基本流起点。

**前置条件：** 注册管理员已登录。  
**后置条件：** 成功则学生信息已增加、更新或删除；否则系统状态不变。

### 5.4 选课注册（Register for Courses）

**简要说明：** 学生可为当前学期的开课班次注册；在学期初加退课期内也可更新或删除已选课程。课程目录系统提供当前学期全部开课班次列表。

**基本事件流**（学生希望选课或修改已有课表时开始）

学生选择以下之一：创建课表、更新课表、删除课表。

**创建课表**

1. 系统从课程目录系统获取可用开课班次列表并展示给学生。
2. 执行“选择开课班次”子流。
3. 执行“提交课表”子流。

**更新课表**

1. 系统检索并显示学生当前学期课表。
2. 系统从课程目录系统获取可用开课班次列表并展示。
3. 学生可通过删除旧班次、从可用列表中新增班次来改选。
4. 系统按所选班次更新课表。
5. 执行“提交课表”子流。

**删除课表**

1. 系统检索并显示当前课表。
2. 提示学生确认删除。
3. 学生确认。
4. 系统删除课表。若课表中含状态为“已注册（enrolled in）”的班次，须将该学生从相应开课班次中移除。

**选择开课班次（Select Offerings）**

学生从可用列表中选择 **4 门首选** 与 **2 门备选**。选定后，系统为学生创建包含所选班次的课表。

**提交课表（Submit Schedule）**

对课表中尚未标记为“已注册”的每个所选班次，系统校验：

- 学生是否满足先修课程；
- 该开课班次是否仍开放；
- 是否存在时间冲突。

通过后将学生加入该开课班次，并在课表中标记为“已注册”，然后保存课表。

**备选流**

- **保存课表：** 学生可随时选择保存而非提交。此时不执行“提交课表”，改为：未标记“已注册”的班次标记为“已选择（selected）”，并保存课表。
- **先修未满足 / 课程已满 / 课表冲突：** 显示错误。学生可改选其它班次并继续、按现状保存课表，或取消操作并回到基本流起点。
- **未找到课表：** 更新或删除课表时检索失败则显示错误。学生确认后回到基本流起点。
- **课程目录系统不可用：** 向学生显示错误，学生确认后用例终止。
- **选课注册已关闭：** 用例开始时若本学期注册已关闭，向学生提示并终止用例。关闭后学生不得再注册。
- **取消删除：** 学生决定不删除课表时，取消删除并回到基本流起点。

**前置条件：** 学生已登录。  
**后置条件：** 成功则学生课表已创建、更新或删除；否则系统状态不变。

### 5.5 选择授课课程（Select Courses to Teach）

**简要说明：** 教授从课程目录中选择自己有资格、并希望在下一学期讲授的开课班次。

**基本事件流**（教授希望报名讲授下学期部分开课班次时开始）

1. 系统检索并显示教授本学期有资格讲授的开课班次列表，同时显示教授此前已选择讲授的课程列表。
2. 教授勾选和/或取消勾选希望在下学期讲授的班次。
3. 系统将教授从被取消的班次中移除。
4. 系统校验所选班次之间、以及与教授此前已报名班次之间**无时间冲突**（相同日期与时间）。若无冲突，则为每个所选班次记录该教授为授课教师。

**备选流**

- **无可用开课班次：** 教授下学期没有任何有资格讲授的班次时显示错误，教授确认后用例结束。
- **时间冲突：** 显示错误并指出冲突课程。教授可通过取消某一授课选择来消除冲突，或取消整个操作（所有选择丢失）并结束用例。
- **课程目录系统不可用：** 显示错误（原文此处误写为向“学生”提示），确认后用例终止。
- **选课注册已关闭：** 用例开始时若本学期注册已关闭，向教授提示并终止。关闭后教授不得再更改所授班次；若仍需变更，在本系统范围之外处理。

**前置条件：** 教授已登录。  
**后置条件：** 成功则教授计划讲授的开课班次已更新；否则系统状态不变。

---

### 5.6 提交成绩（Submit Grades）

**简要说明：** 教授为上一学期已结束的一门或多门课程提交学生成绩。

**基本事件流**（教授希望提交上学期成绩时开始）

1. 系统显示教授上学期讲授的开课班次列表。
2. 教授选择一个开课班次。
3. 系统检索该班次全部已注册学生，显示每位学生及此前已录入的成绩（如有）。
4. 教授为每位学生录入成绩：**A、B、C、D、F 或 I**。系统记录成绩。若某学生暂不录入，成绩可留空，稍后补填。教授也可通过录入新成绩来修改已有成绩。

**备选流**

- **未讲授任何开课班次：** 上学期教授未授课时显示错误，教授确认后用例结束。

**前置条件：** 教授已登录。  
**后置条件：** 成功则该开课班次的学生成绩已更新；否则系统状态不变。

---

### 5.7 查看成绩单（View Report Card）

**简要说明：** 学生查看上一已结束学期的成绩单。

**基本事件流**（学生希望查看上学期成绩单时开始）

1. 系统检索并显示学生上学期所完成各开课班次的成绩信息。
2. 学生表示查看完毕后，用例终止。

**备选流**

- **无成绩信息：** 找不到上学期成绩时显示提示，学生确认后用例终止。

**前置条件：** 学生已登录。  
**后置条件：** 本用例不改变系统状态。

---

### 5.8 关闭注册（Close Registration）

**简要说明：** 注册管理员关闭注册流程。人数不足的开课班次将被取消（最少 3 名学生）。对未取消班次中的每位学生，通知计费系统以便收费。

**基本事件流**（注册管理员请求系统关闭注册时开始）

1. 系统检查注册是否仍在进行。若仍在进行，向管理员显示消息并**终止用例**（注册进行中不得关闭）。
2. 对每个开课班次：若已有教授报名授课且至少 3 名学生注册，则对包含该班次的每份课表**提交（commit）**该班次。
3. 对每份课表进行**调剂（level）**：若首选课程未达到上限，系统尝试从该课表的备选列表中补选。按顺序选用**第一个仍可用的备选班次**；若无可用备选，则不做替换。
4. 系统关闭全部开课班次。此时若某班次仍不足 3 人（部分学生可能因调剂加入），则取消该班次，并从包含它的每份课表中取消该班次。
5. 系统计算每位学生当前学期课表应付学费，并向计费系统发送事务。计费系统向学生寄送账单，其中包含最终课表副本。

**备选流**

- **开课班次无教授：** 若无人报名授课，系统取消该班次，并从包含它的每份课表中取消。
- **计费系统不可用：** 系统在指定间隔后重发请求，直到计费系统恢复可用。

**前置条件：** 注册管理员已登录。  
**后置条件：** 成功则注册已关闭；否则系统状态不变。

## 6. 实现时需特别注意的约束

1. **遗留课程目录只读**：通过开放 SQL 访问 Ingres（DEC VAX），新系统不得回写课程目录；课程维护仍由教务处其它系统完成。
2. **中间层缓存/处理**：遗留库性能差，需用中间层满足 ≤10 秒延迟及其它性能指标。
3. **课表状态**：至少区分“已选择（selected）”与“已注册（enrolled in）”；保存与提交行为不同。
4. **关闭注册的批处理逻辑**：校验进行中状态 → 有教师且满 3 人则提交 → 备选调剂 → 再次按 3 人下限取消 → 计费。
5. **权限隔离**：学生、教授、注册管理员职责严格分离，成绩仅教授可写，学生信息仅注册管理员可改。
